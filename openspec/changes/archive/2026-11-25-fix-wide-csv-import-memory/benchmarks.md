# Замеры широкого предпросмотра — 2026-11-25

Проверен backend чтения страниц CSV 600 × 4000; цель — открыть файл, на котором прежняя широкая проекция DuckDB завершается ошибкой памяти, без увеличения бюджета движка. Машиночитаемые значения: [benchmarks.json](benchmarks.json).

## Условия

- macOS 26.6.2, Apple Silicon arm64, Python 3.12.13.
- Файл: **600 строк данных × 4000 столбцов**, **242 422 890 байт**. Заголовки `n0`…`n3999`, каждое значение — `1234567890`, повторённое 10 раз (100 ASCII-цифр). Разделитель `,`, двойные кавычки, заголовок включён, UTF-8 без BOM, окончания записей LF.
- SHA-256 источника: `6f2b1292a23fa78771413339aa5480cdc52df23603dba64152371314b4d280de`. После всех операций источник сохранил размер и хеш; `source_unchanged=true`.
- Производственный бюджет DuckDB — **512 MiB**, без повышения. Целевой размер входного блока — **8 388 608 байт (8 MiB)**.
- Каждая операция выполнена в отдельном новом процессе. Импорты происходят до запуска таймера операции; `resource.getrusage(resource.RUSAGE_SELF).ru_maxrss` показывает максимальный RSS этого процесса, включая предшествующие импорты. На macOS значение `ru_maxrss` уже задано в байтах; MiB рассчитаны делением на `2**20`.
- Родительский процесс опрашивал файлы отдельного `TMPDIR` каждые **10 мс**. В таблице указан максимальный наблюдавшийся объём временных файлов, без исходного CSV и без размера файла экспорта. Ноль означает отсутствие файлов, замеченных при этом опросе, а не доказательство отсутствия любых краткоживущих записей между опросами.

## Результаты

| Операция | Результат | Время, с | Пик RSS, MiB | Пик RSS, байт | Временный диск, байт |
|---|---|---:|---:|---:|---:|
| Прежний широкий запрос DuckDB | OOM; страница не получена | 0.963 | 524.8 | 550 273 024 | 0 |
| Открытие: offset 0 | 200 строк; has_more=True | 1.468 | 672.3 | 704 970 752 | 4 |
| Следующая страница: offset 200 | 200 строк; has_more=True | 1.997 | 679.5 | 712 556 544 | 0 |
| Переход к концу: offset 200 | 400 строк; has_more=False | 3.480 | 820.0 | 859 865 088 | 0 |

Baseline выполняет прежний путь: `query_page` поверх `SELECT * FROM <CsvFormat().source>` с offset 0 и limit 200, в соединении `Cancellation().connection()`. Он завершился `OutOfMemoryException: failed to allocate data of size 32.0 KiB (511.9 MiB/512.0 MiB used)`. Время и RSS этой строки относятся к ошибке, поэтому их нельзя сравнивать с успешным открытием как показатели одинаково выполненной работы.

Новый путь показал первую и следующую страницы по 200 строк. Переход к концу сохранил существующий контракт: он вернул **400 строк с offset 200**, то есть диапазон строк данных 201–600; это намеренно большая порция, а не первая страница, объявленная концом. Во всех новых операциях возвращены 4000 канонических столбцов.

Результат исправления — успешное чтение вместо прежней ошибки, а не RSS ниже 512 MiB: наблюдаемый пик нового открытия **672.3 MiB**, перехода к концу — **820.0 MiB**. `memory_limit` DuckDB не ограничивает весь процесс, буферы стандартного парсера, Python/Qt или декодирование. Отдельного полного Parquet для предпросмотра не создаётся; при открытии наблюдались **4 байта** временных файлов, в остальных трёх замерах — **0 байт**. Источник этих четырёх байт отдельно не устанавливался; они включены в измерение, а не отброшены как шум.

## Воспроизведение

Из корня репозитория создать отдельный тестовый файл. Режим `x` защищает уже существующий файл от перезаписи:

```sh
.venv/bin/python - <<'PYCODE'
from pathlib import Path
import hashlib

source = Path('/private/tmp/csv-wide-4000-repro.csv')
row = ','.join(['1234567890' * 10] * 4000) + '\n'
with source.open('x', encoding='utf-8', newline='') as output:
    output.write(','.join(f'n{i}' for i in range(4000)) + '\n')
    for _ in range(600):
        output.write(row)
with source.open('rb') as data:
    digest = hashlib.file_digest(data, 'sha256').hexdigest()
assert source.stat().st_size == 242422890
assert digest == '6f2b1292a23fa78771413339aa5480cdc52df23603dba64152371314b4d280de'
print(source, source.stat().st_size, digest)
PYCODE
```

Штатный измеритель запускает каждую операцию в отдельном процессе и опрашивает её временный каталог с интервалом 10 мс:

```sh
.venv/bin/python - <<'PYCODE'
from pathlib import Path
from scripts.benchmark_csv import measure

source = Path('/private/tmp/csv-wide-4000-repro.csv').resolve(strict=True)
for operation in ('open', 'next-page', 'last-page'):
    measure(source, operation)
PYCODE
```

Для отдельного воспроизведения ошибки baseline используется тот же файл и фиксированный производственный бюджет:

```sh
.venv/bin/python - <<'PYCODE'
from pathlib import Path
from csv_workbench.core import Cancellation, CsvFormat, csv_pattern, query_page

source = Path('/private/tmp/csv-wide-4000-repro.csv')
with Cancellation().connection() as connection:
    query_page(connection, 'SELECT * FROM ' + CsvFormat().source,
               [csv_pattern(source)], 0, 200)
PYCODE
```

Последняя команда намеренно должна воспроизвести ошибку прежнего пути; она не запускает новый широкий предпросмотр. Повторные значения времени, RSS и временного диска зависят от среды и нагрузки; приведённая таблица фиксирует один изолированный прогон на операцию, а не распределение или гарантию.

## Границы проверки

Этот отчёт относится к backend исходной `Selection()` без преобразований. Итоговый полный прогон: **345 тестов за 21.09 с**, включая native Cocoa; все проверки Ruff и строгая валидация OpenSpec прошли. Отдельно прошли 22 случая широкого предпросмотра и 61 связанный тест; они покрывают CR/LF/CRLF на границах блоков 1–40 байт, отмену после разбора и обработки записей и явный отказ для непустой преамбулы иной ширины перед заголовком. GUI, автономная сборка и ручная отмена здесь не проверялись; тесты отмены и семантики формата относятся к отдельным регрессиям. Источник UTF-8 не требовал временной перекодировки: наблюдавшиеся 4/0 байт временного диска не переносятся на другие кодировки.

Сортировка, запросы с правками, Save, экспорт, SQL и подготовленные широкие результаты этим исправлением не объявляются работающими без OOM. Замеры на 5 и 20 млн строк не выполнялись. Не проверены другие ОС, произвольная ширина, огромные одиночные записи и пик всего настольного приложения с его буфером таблицы.
