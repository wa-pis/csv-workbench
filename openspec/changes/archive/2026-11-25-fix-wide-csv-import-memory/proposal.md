# Fix wide CSV preview memory

## Why

CSV шириной 4000 столбцов не открывается при существующем бюджете DuckDB 512 MiB: широкая проекция требует памяти на рабочие векторы даже при `LIMIT 1`. Перенос данных в Parquet не устраняет широкую проекцию. Повышение бюджета также не даёт приемлемого общего решения: 1–2 GiB недостаточны для запросов с правками и сортировки, а опыт с 4 GiB сопровождался высоким RSS и ошибкой сортировки.

Этот этап исправляет только открытие и постраничный просмотр широкого CSV без преобразований. Сортировка, запросы с правками и Save широких файлов остаются отдельной будущей работой.

## What Changes

- Сохранить существующий бюджет DuckDB 512 MiB без повышения для широких файлов.
- В `read_page` при исходной `Selection()` и ширине более 2048 столбцов читать CSV стандартным парсером `csv` через существующие `csv_blocks` и `format_records` с целевым размером блока 8 MiB.
- Получать канонические имена и порядок столбцов через DuckDB `LIMIT 0`, не выполняя широкую выборку строк DuckDB; закрывать соединение обнаружения схемы до накопления страницы и сохранять формат, Unicode, NULL и пустую строку.
- Ограничивать выдачу запрошенной страницей и признаком следующих строк, сохранять отмену и не готовить полный Parquet ради предпросмотра.
- Добавить регрессии для 4000 столбцов и повторить измерения времени, пика RSS и временного диска на файле 600 × 4000 размером 242 422 890 байт.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `csv-preview`: открытие и чтение страниц широкого CSV без преобразований через потоковый путь стандартного парсера CSV.

## Impact

Изменяется путь `read_page` только для ширины более 2048 столбцов и исходной `Selection()`. Узкие файлы и пути фильтрации, сортировки, запросов с правками, экспорта, SQL, Save и подготовленных результатов сохраняют существующую реализацию и её ограничения. Приложение не обещает поддержку произвольной ширины или жёсткий предел RSS процесса. Используются имеющиеся парсер и логика предпросмотра; новые зависимости не добавляются. Полноценные широкие операции потребуют отдельного этапа выполнения, а не повышения памяти до успеха.
