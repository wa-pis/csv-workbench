## Decisions

Типы являются метаданными Selection (compare=False), как закрепление: они не меняют фильтры, сортировку или путь пагинации. Правило — (имя, тип, nullable). Отсутствие правила означает text с NULL. Настройки доступны в Edit → Column Types / Validation; проверка запускается отдельной командой. Результат — счётчик строк и ошибок по каждому настроенному столбцу, без хранения всех ошибочных ячеек. Подсветка вычисляется для буфера тем же набором правил; ошибка имеет приоритет над подсветкой поиска.

integer: ASCII-знак и цифры без ограничения разрядности; number: десятичная запись/экспонента без пробелов, конечное double; date: действительная ISO-дата YYYY-MM-DD, годы 0001–9999; boolean: true/false без учёта ASCII-регистра; text: любая строка. Пустая строка допустима только для text. NULL проверяется отдельно через nullable.

Backend строит агрегатный SQL по всей отфильтрованной выборке с дисковыми правками, добавлениями/удалениями. Сортировка для подсчёта не нужна. Скрытые настроенные столбцы проверяются тоже. SQL и локальный валидатор покрываются общими примерами. Cancellation прерывает DuckDB; результат принимается только для неизменившейся вкладки/правок/правил. Изменения сбрасывают результат и отменяют старый job.

CSV: незаключённое в кавычки пустое поле = NULL, заключённое пустое поле = пустая строка. DuckDB allow_quoted_nulls=false; Polars использует стандартную семантику без null_values="". QUOTE_NOTNULL при записи; единственный NULL в строке записывается пустой физической строкой. В таблице NULL и пустая строка различаются текстом/tooltip; «Set NULL» и «Set Empty String» явные операции с Undo. Обычное удаление текста в редакторе даёт пустую строку, Clear cells — NULL.

Старые сессии без правил остаются совместимы. Некорректные/дублирующие правила в JSON отвергаются. Отдельный формат или версия сессии не нужны.
