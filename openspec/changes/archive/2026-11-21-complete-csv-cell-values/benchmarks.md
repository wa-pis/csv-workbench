# Замеры автодополнения CSV

21 ноября 2026 года, macOS Apple Silicon. Python 3.12.13, DuckDB 1.5.6, Polars 1.44.2. Точная платформа и исходные результаты: [benchmarks.json](benchmarks.json).

Воспроизведение:

```sh
uv run python scripts/benchmark_completion.py 5000000 20000000 --output completion-benchmarks.json
```

CSV содержит четыре текстовых столбца: note (`hit`), десятизначный id, category (10 групп), payload (64 символа). Размеры: 435 000 025 байт / 1 740 000 025 байт. Перед каждым запросом создаются две дисковые правки последней строки: id=`id-edited`, category=`group-edited`. Применяется фильтр note contains hit; сортировка id DESC задана в выборке, но не исполняется для поиска значений, поскольку на набор подсказок она не влияет.

Каждый сценарий запускается в отдельном процессе. Время включает запрос, применение правок, запись/чтение временного Parquet и очистку, но исключает генерацию CSV, запуск Python и создание исходных правок. RSS — максимум всего процесса по getrusage (не дельта и не память GUI). Временный диск — максимум суммы размеров файлов в изолированном TMPDIR, включая хранилище правок, с опросом каждые 20 мс, без исходного CSV. Короткие пики между опросами могут быть пропущены. Источник только что записан, поэтому файловый кеш ОС тёплый. Это одиночные прогоны, не статистические гарантии для другого оборудования.

| Строк | Сценарий | Время, с | Пик RSS, МиБ | Пик временного диска, МиБ | Результат |
|---|---|---:|---:|---:|---|
| 5,000,000 | category, пустой префикс | 0.929 | 235.8 | 0.208 | 11 подсказок |
| 5,000,000 | id, пустой префикс | 1.674 | 310.0 | 23.441 | 100 подсказок; усечено |
| 5,000,000 | id, префикс id-edited | 0.709 | 167.7 | 0.084 | 1 подсказок |
| 5,000,000 | Отмена через 0,2 с | 0.213 | 169.8 | 4.153 | Отмена за 6.53 мс |
| 20,000,000 | category, пустой префикс | 3.424 | 275.1 | 0.579 | 11 подсказок |
| 20,000,000 | id, пустой префикс | 6.656 | 410.0 | 93.500 | 100 подсказок; усечено |
| 20,000,000 | id, префикс id-edited | 2.687 | 167.5 | 0.084 | 1 подсказок |
| 20,000,000 | Отмена через 0,2 с | 0.212 | 172.1 | 4.153 | Отмена за 1.81 мс |

Низкая кардинальность даёт 11 значений: десять групп плюс правка. Высокая — первые 100 значений в порядке Unicode и признак усечения. Избирательный запрос находит только исправленный id в последней, не загруженной в GUI строке. Скрипт проверяет содержимое ответов assert-ами.

При увеличении числа строк в четыре раза пиковый RSS вырос с 236 до 275 МиБ для категорий и с 310 до 410 МиБ для id. Python хранит пакет из 8192 значений и максимум 101 кандидата; полный набор уникальных значений в RAM не строится. Временный Parquet содержит только совпавший столбец, поэтому дисковый расход растёт с числом/длиной совпадений. Общий RSS процесса не ограничен жёстко 512 МиБ: это лимит DuckDB, к которому добавляются Polars, Python и буферы чтения.

Замер отмены относится к началу сканирования DuckDB. Отмена на фазе Polars, отмена задачи в очереди и очистка временных файлов дополнительно проверены юнит-тестами. Производительность автономной сборки и других ОС в этом прогоне не измерялась.
