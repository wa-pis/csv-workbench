# Design

## Evidence

Проверяемый bundle: `d507a63`, ARM-артефакт 15152328682. Потоковый unique 6000 × 4000 правильно выдаёт частоты 10. Return отправляется через CUA за 0,02 с, последующее получение окна может занять около 15,8 с и завершиться ошибкой. На сортировке из заголовка наблюдался 30-секундный таймаут.

Без AX native sample показывает основной поток в run loop/отрисовке. Concurrent AX sample показывает `_AXXMIGCopyHierarchy`, `QAccessibleWidgetWrapper` и ожидания `take_gil`. Прямой Python-driven Cocoa обход может недооценивать проблему: между отдельными вызовами он сам держит GIL, в отличие от целого внешнего AX-запроса.

## Decision

Эксперимент с `sleep(0)` на границе CSV-блока и каждой записи не улучшил задержку AX и в production не внесён. Вместо этого `ViewAccessible.focusChild` определяет фактический редактор или текущую видимую ячейку напрямую, учитывая владельца клавиатурного фокуса закреплённого pane. Запрос фокуса не читает `state`/`flags` посторонних ячеек и не создаёт полный список их accessible-интерфейсов.

Baseline нативного обхода с активным фокусом во время реального unique занял 11,516 с; candidate — около 2,84 с. Probe использует один вызов временной Objective-C библиотеки, отпускающий GIL на весь обход. Она нужна только эксперименту и не становится зависимостью приложения. Неактивное окно давало другое распределение задержек, поэтому его показатели не смешиваются с активным.

Глобальный Python switch interval, worker, бюджет DuckDB и семантика CSV не меняются. Для ручной приёмки используется обычный worker без искусственных задержек. Кэш ячеек остаётся ограничен viewport, а сброс модели не возвращает stale token для другой ячейки.

## Verification

Реальный wide fixture с известными частотами, ограниченный viewport и активный worker; Cocoa чтение children/role/focus/value/title; отмена и освобождение ресурсов. Затем полный pytest, Ruff/OpenSpec, standalone build и ручное наблюдение активной отмены и последующей навигации.
