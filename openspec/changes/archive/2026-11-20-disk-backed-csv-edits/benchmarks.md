# Замеры дисковых правок — 2026-11-20

Окружение: macOS 26.6.2 ARM64, Python 3.12.13, DuckDB 1.5.6, Polars 1.44.2. Каждый размер запускается в отдельном процессе. Команда:

```sh
.venv/bin/python scripts/benchmark_edits.py 5000000 20000000
```

Детерминированный CSV: id, note, category, payload (64 символа). В note каждой строки находится `hit HIT`; выборка показывает note, замена `hit` → `new` меняет 5/20 млн ячеек и 10/40 млн вхождений. Создание входного CSV не входит во время операций.

RSS — high-water всего процесса с его запуска (resource.getrusage), а не отдельный пик каждой фазы. Временный диск — максимум суммы логических размеров файлов с опросом каждые 50 мс; входной CSV исключён. Включены план, SQLite/WAL, Parquet, spill DuckDB и журнал восстановления.

| Строк | CSV, МиБ | Предпросмотр, с | Применение, с | Последняя страница, с | Пик RSS всего сценария, МиБ | Пик временного диска, МиБ |
|---|---:|---:|---:|---:|---:|---:|
| 5,000,000 | 433.9 | 9.20 | 8.47 | 3.56 | 1306.4 | 898.9 |
| 20,000,000 | 1735.7 | 37.38 | 34.77 | 15.34 | 1354.8 | 3895.9 |

| Строк | RSS после предпросмотра → после применения, МиБ | Undo / Redo снимка, мкс | Запись checkpoint, с | Восстановление, с |
|---|---:|---:|---:|---:|
| 5,000,000 | 475.5 → 486.7 | 2.4 / 1.6 | 0.14 | 0.35 |
| 20,000,000 | 655.7 → 666.8 | 3.1 / 1.7 | 0.78 | 1.35 |

Undo/Redo здесь измеряет переключение снимка; фоновый пересчёт таблицы в эту величину не входит. Чтение последней страницы отдельно измерено через тот же editable_query, что использует приложение. После Undo проверяется отсутствие правок; после Redo — значения первой/последней строки. Восстановление проверяет число правок, значения и снимок Undo.

Применение увеличило high-water RSS примерно на 11 МиБ при обоих размерах. Основной пик остаётся в чтении/объединении CSV средствами DuckDB и Polars, включая их буферы и аллокаторы; настройка DuckDB 512 МиБ не ограничивает весь процесс. RAM не выросла в четыре раза при увеличении числа правок в четыре раза.

Первый пробный запрос с map(list(...)) упёрся в лимит DuckDB уже на 5 млн строк. Для дисковых правок использованы скалярные агрегаты с spill на диск. Передача SQLite → DuckDB идёт через Parquet порциями до 32 768 записей; применение читает план по 2 048 ячеек.

История удерживает версии, включая отброшенные ветки Redo, до закрытия документа; затем каталог удаляется после завершения использующих его задач. На каждое Save с историей нужна отдельная исходная копия CSV; эта копия не измерялась здесь. Сценарий измерен на четырёх столбцах и одной массовой операции; широкий CSV и несколько последовательных замен потребуют больше диска. GUI вручную и сборки CI в этом этапе не проверялись.
